Security status of this preview

Chromium’s sandbox, site isolation, certificate validation, permissions, WebAuthn, and modern TLS remain enabled. This ungoogled runtime omits Google Safe Browsing and automatic browser updates. It does not provide full Chrome security-service parity. Keep the engine updated before using it as your everyday browser.

Hybrid post-quantum TLS key exchange is inherited from Chromium where supported by the server. This does not make all certificates or connections quantum-safe. Legacy insecure TLS is not re-enabled.

Your keys stay with Apple.

Google website sessions persist in Kumo’s own profile. Apple Passwords remains your password vault.

The native system picker requires Kumo’s source build.

Kumo’s source includes a native “Fill with Apple Passwords…” context-menu action. Its AppKit field uses the system’s AutoFill → Passwords menu, followed by an explicit Fill button. This upstream-binary preview does not include that source change.

The native path uses no Apple browser extension or extension pairing code. macOS controls credential selection and may require Touch ID or device authentication. Automatic website matching and completed credential fills still require verification. Native passkeys separately need Apple’s approved browser entitlement.

Compatibility

Standard websites, web apps, WebGL, WebGPU, WebAssembly, WebAuthn and extension APIs come from Chromium. “Web3” sites can use compatible wallet extensions; no wallet or blockchain gateway is bundled. Legacy Flash, Java, and NPAPI plugins are not supported.

Chrome Web Store downloads use Google’s store/CDN when you choose to install. Install permissions and signature checks remain in Chromium. Store installs, updates, DRM media, and managed extensions need separate compatibility verification.
