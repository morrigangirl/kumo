## Migration and toolchain limits

The release-profile test used mock Keychain access and synthetic HTTP-only fixture
data, with normal browser closure between versions. The extension/settings test
used one owned copied-extension path and a transparent native-API observation hook
only in that copy. Neither accessed real accounts, personal profiles or credentials.
These checks do not establish migration of every profile database, saved password,
third-party extension or production updater installation. The Store checks also
did not download/install a real CRX or fetch Store content from Google.

A separate focused unwind fixture passed all 13 exact commands with the current
Clang 24, Rust 1.100, SDK 27 and verified LLD 23.1.3. C++ catch/destruction,
Objective-C catch/finally, Rust catch/Drop, backtraces through Chromium's actual
assembly frame and its intentional termination boundary passed. Independent
analysis of the new Mach-O matched the frame's FDE/CIE, actual LSDA and chained
personality pointer, and confirmed the compact-unwind entry preserved DWARF
fallback to that FDE. Input hashes and earlier evidence remained unchanged.

That fixture deliberately uses O0, frame pointers, forced exception/unwind tables
and Rust `panic=unwind`; many production Chromium targets use different flags.
Rust catches its panic internally, with no cross-C-ABI unwinding claim. This
focused check does not prove every engine ABI path or arm64e/PAC behavior.
