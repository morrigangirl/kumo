## Change and security scope

The active browser change clarifies the existing manual Apple Passwords sheet:
select the website or app entry and saved account in Apple's chooser, then Fill.
The username and password controls retain their standard native content types;
explicit accessibility labels and help describe the same selection flow.
The browser-owned destination origin, exact renderer field ID, HTTPS/policy and
certificate gates, document revalidation and cancellation behavior are unchanged.
No username history, credential database, new vault access or helper session is
introduced by this change.

The separate pairing geometry and AppKit panel are preparatory source components.
The Chromium overlay does not compile or call them. This release therefore does
not enable an inline account dropdown, session-start pairing or an Apple helper
connection. Live placement against Apple's code-display window is unverified;
only injected synthetic helper bounds are used in the component checks.

The engine remains Chromium 156.0.8078.47. This check is a regression review of
the current point release, not a new Chrome CVE survey or an engine security
version update.
