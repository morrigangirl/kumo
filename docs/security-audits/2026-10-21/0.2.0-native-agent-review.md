# Kumo 0.2.0 native agent review

Reviewed on October 21, 2026 (evidence completed October 22 at 00:30 UTC).
The two findings below are fixed in the authored source. The rebuilt browser's
native smoke tests remain pending; these results do not qualify an app, installer
or release for publication.

## Scope and findings

The review covered `native/browser/agents/kumo_agent_service.cc`,
`kumo_agent_dom.h`, `kumo_agent_pipe.h`, and
`agent-bridge/lib/{broker,protocol}.mjs`. It checked profile, tab, origin and
document authority; revocation; new-tab grants; private browser pipes; DOM
privacy; and worker/process cleanup.

1. **P2: snapshot metadata exposed excluded draft text.** The main text walker
   excluded form values and editable areas, but link/control labels separately
   used `innerText`. This exposed textarea default text, editable link text, and
   private descendants of otherwise public buttons or links. The fix applies one
   private-context policy and filtered public-text walker to all snapshot text
   channels. Controls within editable ancestors are omitted. Ordinary controls
   retain their ID, name, type, explicit label and placeholder metadata; form
   control labels never fall back to their contents. Sensitive password,
   payment, verification-code, hidden and file fields remain excluded.

2. **P2: broker child processes were not reaped.** The original stop path called
   `base::Process::Terminate(0, false)` and `Close()` without waiting. In the pinned
   Chromium POSIX implementation, those calls send SIGTERM and clear the handle;
   they do not reap the child. The fix transfers the owned child exactly once to
   a worker, including concurrent stop paths. The worker verifies direct-child
   ownership with `waitid(..., WNOWAIT)`, allows a two-second TERM grace period,
   then uses SIGKILL if needed and reaps it. Already-reaped/non-child PIDs return
   `ECHILD` and are never signalled. No wait occurs in the browser UI stop method.
   Exclusive ownership is required: no other code may reap this child with a
   process-wide wait.

No additional actionable authority bypass was identified in this review.
Session grants still begin disabled, remain restricted to the same ordinary
profile and granted origin, and undergo native document/epoch checks before
results are returned. Socket peers cannot acquire the private browser role or
publish grants. The fixes do not add commands, arbitrary script execution, shell
access or permission persistence.

## Verification

- Six DOM tests passed, including textarea/select defaults, editable ancestors,
  hidden descendants, and public buttons/links containing private descendants.
  The new regression fails against the original frozen header and reproduces
  the leaks, then passes against the fixed shipping script.
- Eight compiled tests exercised the actual shipping process helper against real
  disposable children: graceful exit, prior exit, ignored TERM, stopped child,
  concurrent ownership transfer, already-reaped PID, live non-child, and invalid
  or current PID. Compilation used `-Wall -Wextra -Werror`.
- All 26 Node agent tests passed in the normal execution environment. The first
  sandbox run recorded five `listen EPERM` failures and two dependent ready
  timeouts. That failed attempt is retained; one retry with disposable Unix
  socket listeners permitted passed all tests.
- The browser smoke harness passed syntax checking and its non-browser self-test.
  Its pending native runtime fixture now includes the nested draft cases.

No browser was launched, no real profile or credentials were accessed, and no
desktop provider configuration was changed during this verification. Full
browser integration, actual `AgentPipe` shutdown in the browser, and packaged
application qualification remain pending.
