## Verified capabilities

| Capability | Public route and boundary |
| --- | --- |
| Website passkeys and security keys | Preserve Chromium's native WebAuthn path. `ASAuthorizationWebBrowserPublicKeyCredentialManager` can report/request browser passkey permission and list passkey metadata for a relying party. It does not return saved passwords or private key material. |
| Arbitrary relying parties for browser passkeys | Apple's `com.apple.developer.web-browser.public-key-credential` managed capability requires approval and correct signing/provisioning. Local entitlement text is insufficient. |
| An app's associated website password | `ASAuthorizationPasswordProvider` participates in shared web credentials for associated domains with website cooperation and user consent. This is not a browser-wide website password retrieval API. |
| Native AppKit manual AutoFill | `NSTextField.contentType = .username` and `NSSecureTextField.contentType = .password` are public on macOS 11+. The empty-field probe showed an enabled system AutoFill → Passwords menu for both fields on macOS 27.0.1. Credential selection/completion was deliberately not exercised. This could support a browser-owned manual fill sheet without the Chrome extension; it does not demonstrate automatic website matching. |
| Save/update password through `ASCredentialDataManager` | The macOS 27.0 Swift SDK explicitly marks `save(password:for:title:anchor:)` unavailable on macOS. Its cross-platform documentation must not be treated as Mac availability. The reporting methods do not retrieve passwords. |
| Open Apple Passwords | Launch the installed application through public `NSWorkspace` APIs; the user unlocks and selects credentials. No automatic fill or domain-specific deep link is claimed. |
| Apple's iCloud Passwords browser extension | Retain Chrome extension compatibility. Apple's extension remains subject to Apple's browser support and authentication behavior. Kumo cannot guarantee support or remove pairing requirements. |

Apple's browser-password documentation collection currently links public-key credential APIs; its title is not evidence of a general password retrieval API. `ASAuthorizationPasswordRequest` in the inspected SDK has no browser relying-party or arbitrary-URL selection field. No public API verified here grants an arbitrary Chromium browser seamless access to all website passwords.

## Implemented here

`native/apple-passwords` builds a Swift library, the `kumo-apple-passwords` diagnostic, and a native `kumo-autofill-probe` app. `status` reports API and app availability without requesting authorization or reading credentials. The library offers a public browser passkey authorization request and opens the Passwords app using Launch Services. The separate AutoFill probe contains two empty standard AppKit fields with the correct semantic types; it does not log, persist, export, or send their contents anywhere. These functions are not yet wired to Chromium settings or forms. The diagnostic's permission applies to its own process identity.

`native/chromium/kumo_password_panel.h` and `.mm` implement a source-native browser sheet API using public AppKit controls. `ShowKumoPasswordPanel` displays a fixed canonical destination origin and a semantic username or secure password field, then returns a value only after an explicit Fill action. Cancel, window close, and `CancelKumoPasswordPanel` dismiss it with no value. The field/editor are cleared before callback delivery; credentials are not logged, persisted, copied to the clipboard, or sent to an extension. The adapter in `kumo_password_context.mm` revalidates the document, HTTPS destination origin, exact field renderer ID, and Chromium's certificate/page/policy filling checks before calling Chromium's password driver. It cancels on navigation, tab hiding, minimization, frame deletion, or closure. Merely covering the selected tab with another window does not cancel, so system authentication UI can remain open. The source overlay adds the context-menu command and links these files. All three integration translation units compiled and linked through Chromium's normal build into the signed .84 source app.

## Additional Security and UI SDK audit

| Framework/API | Concrete finding |
| --- | --- |
| Security `SecRequestSharedWebCredential` | The public header and documentation require the requested domain to match the app's associated-domain entitlement. Passing a null domain searches those entitled domains, not every website. It is deprecated in favor of `ASAuthorizationPasswordRequest`. No call was executed. |
| Security `SecItemCopyMatching` | A general keychain query does not grant new access. For the data protection keychain, searches are bounded by the app's signed, provisioned access groups. Setting `kSecAttrSynchronizable` changes synchronization matching; it does not authorize Apple's credential groups. No keychain query was executed. |
| Legacy `SecKeychain` / file-based keychain ACLs | Apple's TN3137 distinguishes legacy file-based storage from the data protection keychain required for iCloud Keychain. A legacy password query or ACL prompt is not equivalent to access to the current Apple Passwords vault. Legacy APIs can still be useful for credentials explicitly saved to that legacy store. |
| AppKit `NSTextContent` | Public semantic labels enable native system AutoFill UI; this is the positive probe result above. The inspected protocol exposes `contentType`, not an arbitrary website origin or a general vault reader. A manually selected credential may still be usable through this native UI. |
| BrowserEngineKit `BEAutoFillTextSuggestion` | Its declaration is enclosed by `BROWSERENGINEKIT_HAS_UIVIEW`, which requires UIKit headers. A native macOS Swift compile-only probe cannot find this type. The UIKit browser text-input route is not an AppKit Chromium adapter. |
| SafariServices `SFSafariSettings` | The macOS 27 header exposes a query for Safari's AutoFill setting. It does not return credentials. Safari extension APIs operate in Safari; they do not add native Chrome extension-free password fill to a Chromium view. |
| WebKit `WKContentWorld.Configuration.autofillScriptingEnabled` | New macOS 27 API grants extra script behavior inside a WebKit content world. Its documentation does not promise general Apple Passwords access. It applies to WKWebView content, not Chromium's Blink renderer. Switching the rendering engine would change the user's Chromium requirement. |

`native/apple-passwords/audit-public-sdk.py` reproduces three compile-only checks: standard AppKit fields and scoped password-request declarations compile; native macOS BrowserEngineKit AutoFill suggestion type is absent; macOS password saving through `ASCredentialDataManager` is rejected as unavailable. It never runs a credential API. All checks matched expectations against both the earlier 26.5 SDK and the current 27.0 SDK compiled with Swift 6.4. The audit reports the selected compile SDK separately from the default `xcrun` SDK and accepts an explicit `--sdk` path. The installed SDKs include AppKit, AuthenticationServices, and Security. Their native semantic-field UI supplies the manual-picker candidate; adding another import or choosing Swift versus Objective-C does not expand the documented vault-access permissions.

No code reads Apple's password database, exports credentials, impersonates a supported browser, modifies Apple helpers, uses private APIs, reads the clipboard, or suppresses authentication. Apple or macOS can require consent, Touch ID, a device password, or additional verification; avoiding a repeated extension code does not authorize bypassing these controls.

For a release, validate native passkeys with the approved, signed Kumo app, its real bundle identity and provisioning profile. Exercise allow/deny, cancellation, registration, assertion, cross-origin iframe policy, private browsing, and navigation cancellation in Chromium's existing WebAuthn tests. An unsigned diagnostic does not establish production support. Automatic domain-matched password retrieval would require an additional documented macOS browser API or a supported integration arrangement for Kumo.
